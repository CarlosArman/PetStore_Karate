Thank you for your interest in contributing.

This project aims to preserve a clean, readable, and CI-visible API automation repository with Karate.

---

## 1. Contribution Principles

Please keep contributions aligned with these principles:

- readability first
- maintainability over shortcuts
- CI-friendly automation behavior
- clear documentation for workflow execution
- consistent tagging and environment usage

---

## 2. Useful Contribution Types

- new API scenarios
- richer environment/tag examples
- workflow improvements
- documentation improvements
- report publication improvements
- repository structure clarification

---

## 3. Suggested Workflow

1. Fork the repository
2. Create a dedicated branch
3. Implement the change with clear scope
4. Update documentation if needed
5. Validate locally and, when relevant, through CI
6. Open a pull request with a clear explanation

---

## 4. Branch Naming Suggestions

```bash
feature/add-pet-endpoints
fix/improve-workflow-inputs
docs/update-petstore-readme
chore/improve-report-publication
```

---

## 5. Pull Request Expectations

A good pull request should explain:

- what changed
- why it changed
- whether workflow behavior changed
- how it was validated
- whether documentation was updated

---

## 6. Documentation Responsibilities

Update the relevant files when appropriate:

- `README.md` / `README.es.md`
- `docs/COMMANDS*.md`
- `docs/ENVIRONMENT*.md`
- `docs/ARCHITECTURE*.md`
- `CHANGELOG*.md`

---

## 7. Automation Style Guidelines

Recommended practices:

- keep execution examples clear and minimal
- keep environment/tag behavior explicit
- keep CI workflow inputs documented
- preserve report publication clarity
- avoid undocumented workflow changes

---

## 8. Final Note

The best contributions improve the project without making local execution, CI usage, or public report review harder over time.
